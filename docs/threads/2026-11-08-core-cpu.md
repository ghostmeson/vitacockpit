# CORE CPU readout and review — 2026-11-08

## Goal

Make the CORE hero panel useful without a taiHEN system plugin. It had been
reduced to memory only after the applied-clock bridge was removed (D99).

## What shipped

Commit `1910e0f`:

- Four per-core CPU percentages from `sceKernelGetSystemInfo()`.
- Active-core average and a fixed 0-100 % 20 s CPU-load trace.
- Context-switch and wakeup rates per second.
- The three memory pools stay as the second row.
- GPU work is represented by CDRAM/PHY and the pinned FRAME strip. Applied GPU
  clocks and GPU load are unavailable in userland, so no fake row was added.
- `D103` records the decision and supersedes D6.

Commit `d26190f` corrected the documentation after the code review: the
idle-clock unit guard is one-sided, the trace claim matches what the host tests
actually assert, the architecture row names the policy file, and the example
copies were regenerated.

Commit `bbd6e67` closed the behavior and coverage findings:

- `CTX` and `WAKE` have independent validity flags. A cumulative total that is
  zero, frozen, or lower than the previous sample renders `--` for that field,
  never a fabricated `0/S`.
- `ui/core_text` is the pure CORE formatter, linked by the host UI tests, so
  the per-core and caption `--` paths are asserted rather than only drawn.
- The preview gains a CPU-absent scene and a two-active-core scene.
- `cpu_active_mask` is deleted; the rate tests now set the fake rates
  explicitly, and a counter-total hook pins the regression case.

## Review

The independent review is in
[../reviews/2026-11-08-core-cpu/report.md](../reviews/2026-11-08-core-cpu/report.md).
Verdict: **Ready with fixes**.

Resolution:

- #2 fixed in `bbd6e67`: per-field `cpu_ctx_valid` / `cpu_wake_valid`, with
  zero, frozen, regressed, and independent-counter tests.
- #3 fixed in `bbd6e67`: `ui/core_text` formatter tests plus the
  `preview-cpu-absent.png` and `preview-cpu-partial.png` scenes.
- #5 fixed in `bbd6e67`: `cpu_active_mask` removed; `fake_set_cpu_activity()`
  is used by the rate tests and a counter-total hook covers the regression.
- #1(b) remains by design: a coarser-than-microseconds `idleClock` is not
  detectable from the counter; the hardware checklist treats a static 100 % at
  idle as unavailable.
